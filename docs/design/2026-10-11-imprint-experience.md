# Kari Imprint：以照片为中心的交互重构

状态：设计建议，未实现、未部署。2026-10-11。

## 结论与研究边界

需要改。目标不是成为完整修图软件，而是让用户从 Immich 选一张照片，快速获得克制、可靠、可重复编辑的摄影信息框成品。

本轮实际读取了 Lightroom Classic 水印编辑器、打印输出和 darktable 边框官方文档。未完成所有品牌/厂商穷举，也没有验证 Capture One、手机厂商相机水印的当前版本；不能把以下建议说成行业统一结论。

## 官方参考与取舍

| 已核实的参考 | 我们采纳的原则 | 不照搬的部分 |
| --- | --- | --- |
| Lightroom 水印可保存/更新预设；支持 inset、九点 anchor，以及逐张预览。[1] | 样式可复用；位置与间距独立；切照片可看效果 | 不提供任意覆盖照片的九点贴纸布局，保持摄影信息框定位 |
| darktable 分开控制边框尺寸、最终比例、照片位置、边框线尺寸/偏移，并支持自动方向。[2] | 几何职责分清；方向变化有确定规则；照片优先 | 不引入多层边框，不把全部几何参数摆进初始面板 |
| Lightroom JPEG 输出明确用质量控制有损压缩。[3] | 导出明确写“压缩，不缩放”，不宣传无损 | 不照搬打印分辨率/打印锐化等无关选项 |

“高级感”在本方案中是设计判断，不是研究证明：稳定留白、明确文字层级、少量信息、统一对齐、品牌图形不过度抢眼，比增加装饰有效。默认不加阴影、渐变、描边或多层框。

## 一条主流程

相册 → 照片瀑布流 → 单图编辑 → 保存到 Immich → 查看成品或继续下一张。

- 相册页不出现编辑控件；返回恢复相册、滚动位置和选中照片。
- 成品相册不能作为编辑来源；用只读标签说明原因，不以灰色按钮代替解释。
- 照片卡片只标注“未制作 / 有成品 / 有草稿 / 处理失败”，不展示 REV、GEN、job ID。
- 点击照片直接进入预览，不先弹配置对话框。
- 切照片隔离旧请求；输入框聚焦时方向键编辑文本，不触发切图。

## 桌面布局

顶部：返回相册 · 照片名 · 上一张/下一张；右侧只显示草稿/保存状态。

中间：左侧大预览（适应窗口 / 100% / 原图对比）；右侧约 320–360px 的设置栏。设置栏独立滚动，不能覆盖预览或底部操作。

底部：输出目的地 + 主按钮“保存到 Immich”。本地下载作为次操作，不共用含义模糊的“导出”。

右栏分三层，首屏只展示第一层：

1. **样式**：经典信息框、极简署名、纯留白三张可视卡片；都只有一个框。切换样式可撤销，不自动保存成品。
2. **常用调整**：信息条位置（下/左/右）、留白、照片信息、Logo、署名。
3. **精细调整**：字级/字重、信息顺序、间距等。只展示当前样式和选中对象实际支持的选项。

点击预览中的文字或 Logo，右栏定位并高亮对应设置；不进入自由拖拽排版。键盘用户也能通过具名按钮选中同一对象。选中轮廓和辅助线不进入成品。

## 手机布局

上方保留预览；下方“样式 / 信息 / 品牌 / 留白”切换低高度设置抽屉。展开编辑时可收起预览，但保存操作始终可达；考虑安全区和软键盘，禁止嵌套双滚动与遮挡。不能仅把桌面长表单缩窄。

## 单框与默认值契约

- 信息条只能有一个，切换方向是移动同一个条，不创建新层。后端也校验单框。
- 信息条在底部：上/左/右留白默认 60px；在左侧：上/下/右 60px；在右侧：上/下/左 60px。信息条所在侧由条自身厚度管理，不再叠加 60px。
- 60px 指原图像素坐标的扩展留白，预览按缩放比例呈现；不是 CSS 像素，也不缩小原照片。
- 默认上方信息行：中号、粗体；下方参数行：中号、常规字重；参数以空格分隔。横向布局对应原先左上/左下，侧栏则映射为主/次信息行，避免方位命名误导。
- Fuji 使用 Kari 提供的图形。品牌可自动识别或手选；识别不明时提示选择，不能猜品牌。该选择默认只影响当前照片。
- Logo 以可见图形边界计算安全区。分隔线到图形、图形到外侧内容边界的空白相等；左右侧栏使用同一旋转坐标规则。不得仅按含透明边的文件尺寸居中。
- 极端长镜头名或缺失 EXIF 时，按既定截断/换行策略保持边界，不显示 undefined、空分隔符，也不挤压 Logo。截断项可在设置里查看全文。
- “自动”必须明确显示自动和实际生效值；禁止控件显示一个常量而渲染用另一个继承值。

## 编辑、重置、样式的作用范围

所有常规编辑只影响当前照片草稿；切换来源相册不应暗中生成另一套同照片配置。若未来需要“每相册独立样式”，应单独设计身份模型，不借 UI 偷换语义。

- 默认样式为产品默认。首期不加入全局默认编辑器，避免“改本图还是改全部”歧义。
- “重置为默认”只重置当前草稿，不写服务器、不覆盖成品；立即提供撤销。
- 撤销/重做覆盖调整、切样式与重置；保存后仍可继续编辑。
- 未保存离开：提供“保存草稿并离开 / 放弃修改 / 继续编辑”。草稿持久化必须按用户+照片隔离；在真正具备恢复能力前不得显示“已自动保存”。
- 高级参数若布局引擎不支持，就删除或禁用并说明原因，不能保留无效滑块。

## 保存必须形成闭环

保存前可直接看到：目的相册“旅行 Imprint”、原图不变、已有成品会更新。

正常状态：准备 → 生成 → 写入成品 → 等待 Immich 收录 → 已保存。只有查到 Immich 目标资源与目标相册关系才显示“已保存”，不能把本地写盘成功当成全链路成功。

- 处理中防双击；幂等身份绑定用户、源资产和受控输出目标，不按文件名猜测覆盖对象。
- 超时显示“已生成，仍等待 Immich 收录”与重查入口；不永久转圈、不伪报失败。重试复用同一任务/结果身份，避免重复图片。
- 完成后显示“在 Immich 查看”和“下一张”。链接不可用时不能造地址。
- 失败在原界面保留草稿，显示可操作原因：照片移出相册、权限不足、生成失败、同步待恢复。详细诊断藏在展开区。
- JPEG 默认 quality=85、subsampling=2，属于有损压缩；不缩放原照片，追加边框后总尺寸变大。PNG 保持 PNG，不能承诺同样压缩率或 8MB 上限。

## 先修可靠性，再改外观

以下来自本项目已有对抗审查，详见 `../audits/2026-10-11-adversarial-review.md`；此文不代表重新验收：

P0：面板 owner 授权约束、真实 Immich 相册成员校验、输出归属与幂等、导出终态闭环。当前“照片已不在所选相册”不能仅改提示语掩盖。

P1：TS/Python 布局一致性、三方向 Logo 安全区、单框端到端约束、默认值和无效控件、注销接口。

P2：实施上述浏览/编辑/保存界面、上下文选择、撤销重置、移动端和键盘支持。

顺序不是三次面向用户的半成品交付；完成关键链路后再提供一版可实测版本。保留已有工作区修改，不在生产环境直接开发。

## 验收门槛

1. 真实 Immich 契约测试不再伪造 album.assets；普通用户、非 owner、照片跨相册、成品相册、删除照片均覆盖。
2. 连续点击保存、失败重试、刷新等待状态，都不产生重复输出；实际验证目标相册关系。
3. TS/Python parity 通过；横竖照片 × 下/左/右信息条截图对比；Logo 间距用几何断言，不只肉眼看。
4. 默认值、60px 留白、无分隔符、上下文字字重均核对真实渲染输出，不只核对控件初值。
5. 桌面窄窗口、手机、200% 页面缩放无重叠；Tab 可到全部操作，焦点可见，错误不只靠颜色。
6. 重置可撤销、返回不丢状态、旧请求不回写；修改草稿不改变已发布成品。
7. 修复过期浏览器测试后重新跑；本地通过与 NAS 部署通过分别记录。部署前一致性备份，部署后 health、真实生成与回滚路径验证。

验收目标：第一次进入不用理解 Region/Slot/Revision 就能完成一张；常用操作不进高级面板；任何时刻都知道正在改哪张、改动是否保存、成品去了哪里。需通过真实使用验证，当前不宣称已达成。
